The event log: the `llm_call`, `eval_score`, `llm_wire`, `session_transcript` and journal tables, their ports, and the Parquet adapter (which also stores the durable store's sealed journals, behind tars-storage's port).

- Role (hex): port + adapter(Parquet)
- Effect budget: fs (Parquet log files + `_live.json` manifest + partition `flock` + `_store_id`, and opening a durable store file — `parquet` feature only) | net (uploading frozen past-day files to the deployment's bucket through `object_store`; the S3 / GCS / Azure clients only with `object-store-cloud`, configured from the SDKs' own `AWS_*` / `GOOGLE_*` / `AZURE_*` variables)
- Deps: may depend on [tars-types, tars-utils, tars-storage (`parquet`, for the durable store journal port `ParquetTrajectoryLog` implements), tracing (the macros only), thiserror, serde, serde_json, sha2, uuid, tokio, async-trait, bytes, parquet + arrow-array + arrow-schema + fs4 + percent-encoding + chrono + itertools + object_store + url (`parquet` feature)]; MUST NOT import [tars-llm → the emitting side must depend on melt, never the reverse]
- Owns concepts: [durable_file::{open, open_existing, journal_dir} — a durable store file opened with its sealed journals in Parquet beside it (`parquet` feature); event::call_log::{LlmCallTable, LlmCallRow, CallOutcome, CallResponse, CallBody, EvalScoreTable, EvalScoreRow, CALL_LOG_SINK, CALL_LOG_COMPACTION} — the call log (b/61): one `llm_call` row per call with both bodies inline (a body is `present` or `withheld`, never null; a file missing a column this build writes does not read), one `eval_score` row per score, Parquet partitioned `tenant=<t>/<table>/date=<call day>/`; event::wire::{WireTable, WireRow, Transport, WireOutcome, WIRE_LOG_SINK, WIRE_LOG_COMPACTION, attempts} — the wire log (b/150): one `llm_wire` row per attempt a provider's transport made for a logged call, the bytes sent and received verbatim (HTTP: the request body; a subprocess: its stdin, with its spawned argv in `argv` and its stderr in `stderr_bytes`, both null on HTTP) and how the attempt ended (`completed` once the provider sent its end / `failed` with the error as raised / `cancelled` when dropped before that), written by that transport only, partitioned by the call's day like `llm_call`; event::session_transcript::{TranscriptRow, SessionTranscript} — a session's conversation, one row per jsonl line kept verbatim, partitioned by the day the session opened (opened by its writer as a `ParquetLog`, not through `EventLogs`); event::event_logs::EventLogs — opens an event-store directory's `llm_call` / `eval_score` / `llm_wire` logs (feature `parquet`, b/77), and with `ship_to` makes their sinks upload each past day's frozen files to a bucket, named `<store id>.<file>` under the local partition path, on an upload task that backs off after a failure; event::log::{LogTable, Partition, LogSink, LogSource, SealPolicy, BufferedSink, MemLog, ParquetLog, ParquetTable, CompactRule, LogError} — the append-only log mechanism (b/36): rows buffer, seal by policy, only sealed rows are readable; a Parquet partition's files merge by an injected `CompactRule` (16 → 1 per level, a past day → one file), merged-away files kept as `retired` for `grace` under `<file>.retired`, so a glob of `*.parquet` under a partition reads exactly the live files (b/62, b/588); pure seal core + shared sink shell + per-adapter `SealWriter`; every adapter passes `event::log::contract`; event::log::ParquetTrajectoryLog — the durable store's sealed journals as `<root>/task_journal/<name>.parquet`, implementing `tars_storage::durable::journal::TrajectoryLog` (feature `parquet`)]
- Reason to change (the ONE): the event log's contract or schema changes
- Belongs here: a new log table; a Parquet layout or merge rule; how frozen files reach the bucket
- Does NOT belong: emitting events during a request → tars-llm (EventEmitterMiddleware calls in); a run's trajectory → the durable store (tars-storage), which hands melt only the journal rows to seal; the journal port and its row types → tars-storage (`durable::journal`); reading events for a CLI view → tars-cli (`tars events`); installing the subscriber or exporting telemetry → tars-telemetry
