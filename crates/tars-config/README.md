Declarative configuration for TARS: the schema, loader and validator of the immutable config layers (an optional system file, then `<tars home>/config.toml`), the merge and source of each operator setting (`[llm.retry]` and the like) whose type its owner crate keeps, and the model catalog (which models each provider has and their limits) read from the shipped `data/provider.toml` and the home's `models.json`. It declares providers but never instantiates them.

- Role (hex): core (config schema, model catalog) + adapter(fs: TOML loading, `models.json` reading and writing)
- Effect budget: fs (reads `config.toml` and `models.json` from the tars home or an explicit path; writes `models.json` atomically when `tars models update` saves a listing) | env (`$TARS_HOME`, and the user's home directory, to find the tars home; `$TARS_SYSTEM_CONFIG` to find the system file) | process-wide state (the installed config and catalog, each installed once)
- Deps: may depend on [tars-types, tars-utils, tars-sandbox (`SandboxConfig` → `SandboxPolicy` resolution), serde, serde_json, toml, figment, thiserror, tracing, dirs]; MUST NOT import [tars-llm → instantiation lives in `ProviderRegistry::from_config()`, which depends on this crate, not the reverse (lib.rs states the ban); reqwest → no network at config time; sqlx / rusqlite → a store crate opens the database]
- Owns concepts: [Config (`Config::load_file` / `Config::from_toml`, every one validated), ConfigError, ProvidersConfig, ProviderConfig, ProviderKind, RoleConfig, SandboxConfig / resolve_policy, builtin provider defaults + merge, `Config::load_layers` / `LayerPaths`, `load_tars` / `install` / `init_tars` and the process-global config, the operator layers (`operator`: `FileLayer`, `Section`, `SettingSource`, `Effective`, `OperatorLayers::take` / `finish`), resolve_home, default_config_path, the store file names under a consumer's `store_dir` (`get_*db_path`, `durable_store_path`); the model catalog: `model_kb` (the shipped `data/provider.toml`), `model_library` (`models.json`, written by `tars models update`), `model_catalog` (the two layered, and the process-global catalog), `model_spec` (`<series>@latest`)]
- Reason to change: the user-facing configuration schema changes (a new declarable knob); and, separately, the model catalog changes (a vendor ships a model or changes a limit or price). The two change at different rates; whether the catalog stays here is an open question (review py-config Q1)
- Belongs here: a new `[providers.X]` field + its validation; a new operator `Section` variant (its type and default stay in the owner crate); a builtin default; a path-resolution rule; a field of `data/provider.toml` and how it layers under the live list
- Does NOT belong: building an OpenAiProvider from a ProviderConfig → tars-llm registry; reloading the config at run time or overlaying it per tenant → a process serves one tenant and installs one config, once (`global.rs`); secrets fetching (vault, network) → a future secret-manager adapter, not the schema crate; an operator section's fields, default or validation → the owner crate's type (`RetryConfig` in tars-llm), which a composition root names in `take`
